Technology

Built for Speed, at Every Layer

🗃️

Why Apache Cassandra?

At 20 Hz per car, a 20-car grid produces 400 writes per second. Cassandra's wide-column, append-only model handles this without write amplification. Queries by (race_id, car_number, timestamp) map directly to partition keys, giving sub-millisecond reads for the last 60 seconds of history.

🧹

Real-Time Data Cleaning

Sensor noise, duplicates, and out-of-range values are flagged before storage. Our pipeline uses Z-score validation on a rolling 5-second window and deduplication by sensor_timestamp. The /quality endpoint exposes quarantine rates per reason so you can inspect health live on the dashboard.

✗ speed_kmh: 9999 → quarantined (out_of_range)
✓ speed_kmh: 287.4 → stored, quality_flag: "ok"
🤖

ML Predictions, Simply Explained

An XGBoost classifier is trained on historical F1 stint data. Every second, it receives a feature vector of 60-second rolling averages (tyre wear slope, brake temp trend, G-force variance) and outputs a pit probability between 0 and 1. Green < 0.4 · Amber 0.4–0.7 · Red > 0.7.

Model: XGBoost v1.0 · Latency: ~12 ms
